# Molkky Fun

モルックの試合を記録する、React 製のフロントエンド Web アプリです。ゲームデータはブラウザーのローカルストレージに保存されます。ライブ共有ではPeerJSの公開シグナリングサーバーとSTUNを利用し、試合データはWebRTCで直接配信します。

## 開発

1. Dev Container でリポジトリを開く（または Node.js 22 以降と Corepack を用意する）
2. `corepack enable`
3. `pnpm install`
4. `pnpm dev`

## ルール

- 1本だけ倒した場合はピンの数字、複数本の場合は倒した本数が得点です。
- 合計50点ちょうどで勝利し、50点を超えると25点に戻ります。
- 3回連続でミスすると失格になり、残り1人（チーム戦では1チーム）になった時点でその人（チーム）の勝利となります。
- 個人戦とチーム戦に対応しています。参加人数は2人以上です。
- チーム戦ではチームごとに1投ずつ交代し、チーム内の選手は設定した順に投げます。各チームの人数は揃っていなくても構いません。
- チーム戦では得点と3回連続ミスをチーム単位で集計します。
- ゲーム開始前に選手の順番（個人戦）またはチーム順・チーム内の選手順（チーム戦）を並べ替えられます。個人戦の選手順、チーム戦の選手のチーム振り分け・チーム順・チーム内の選手順は、それぞれランダムに決めることもできます。ランダム振り分けでは各チームの人数差が最大1人になります。
- 新しい試合を始めるときは、直前の試合の形式・選手・チーム分け・投球順を引き継ぎ、必要に応じて編集できます。

## 表示言語

初期表示は日本語です。メニューの「設定」内の「言語 / Language」で English を選ぶと、登録・試合・結果・分析・ライブ共有・モルック入門・操作説明を英語で表示します。日時も選択言語に合わせます。設定はこの端末・ブラウザーに保存し、次回も引き継ぎます。保存領域が使えない場合も、その起動中は切り替えられます。

言語設定は試合データと別に保存します。選手名・チーム名・試合履歴は書き換えず、JSONの読み込み・書き出しやライブ共有にも言語設定は含めません。画像共有は現在の表示言語を使います。

翻訳は `src/i18n.ts` と `src/locales/en.ts` で管理します。日本語の文言をキーとし、数値や名前は `{0}` などのプレースホルダーで渡します。

## セット先取・設定

メニューの「設定」で1〜5セット先取と入力モードを指定します。設定は専用キー `molkky-fun.settings` に端末内の現在値として保存し、次に開始する試合へコピーします。JSONの共有データ `molkky-fun:data` には端末設定を含めず、読み込みでも端末設定は変更しません。試合内の `settings` はその試合のルールとして保持します。以前の `molkky-fun:data` 直下にあった設定は、専用キーが未保存なら起動時に引き継ぎます。進行中の試合の設定は固定です。言語はその場で切り替えられます。1セット先取は従来と同じ1セットの対戦です。個人戦・チーム戦ともに3人・3チーム以上に対応します。

セット終了後は確認画面で最終投球を取り消せます。未確定状態も自動保存するため、再起動後に確認・取り消しを続けられます。確定するとセット獲得数に反映し、先取条件に達していれば試合履歴へ保存します。未達の場合は次セットの準備画面になります。確定済みセットは編集しません。

次セットはチーム間の順番をローテーション案として提示し、大会規定や対戦相手との合意に応じて並べ替えられます。チーム内の順番は前セットから引き継ぎ、開始前に変更できます。セット中はどちらも固定です。得点・ミス・失格はセットごとにリセットします。大会固有の先攻選択権やモルックアウトを自動判定する機能は含みません。

保存形式は `currentMatch` と試合単位の `history` を持ち、試合内に参加者・開始時設定・`sets` を保存します。各セットは投球順・投球記録・確定状態を持ち、勝者と獲得セット数は記録から計算します。`version: 1` は維持し、旧 `currentGame` 形式を `readMatchData` が1セット先取へ変換します。旧データの終了済み試合は確定済みとして移行し、既存の履歴・勝敗を維持します。

結果画面は試合全体のセット獲得数とセット別分析を表示します。個人成績の試合数・勝利数・勝率は試合単位で集計し、参加セット数・セット勝利数を別に表示します。投球指標は完了した試合の全セットを対象とします。

## 簡易入力と詳細入力

メニューの「設定」で入力モードを選びます。新規登録の初期値は簡易入力で、試合中は変更できません。登録画面にも設定の概要と変更ボタンを表示します。

- 簡易入力：1〜12点をタップすると即記録します。0点は下部の「今回はミス」。間違えた場合は投球履歴のUndoで取り消せます。
- 詳細入力：倒れたピンを選び、下部の得点ボタンで記録します。

どちらも得点・勝敗・成功率・平均得点・10点以上率・あがり成功率などの共通分析に使います。個人分析では、詳細入力の終了済み試合だけを対象に、1本倒しはピン番号別（1〜12）、複数本倒しは倒した本数別（2〜12）の回数を棒グラフで追加表示します。両グラフはそれぞれの回数に合わせた縦軸を使い、対象回数・各棒の数値と、折りたたみ式の数値一覧を表示します。ミスは両グラフに含めません。対象試合数・投球数を明示し、簡易入力の欠けたピン情報を0回やミスとして補完しません。狙ったピンは記録しないため、ピン別の命中率ではありません。

新規投球は `points` を必ず保存し、詳細入力だけ `pins` を保存します。`inputMode` がない旧試合は詳細入力として読み込み、`points` がない旧投球は `pins` から得点を計算します。旧形式は読み込み時に試合・セットの内部形式へ正規化し、次回の自動保存・書き出しは統一形式を使います。過去のルール属性と投球結果は維持します。同じメンバーで再スタートすると試合開始時の設定を維持します。新しい試合には「設定」で指定した次回用の設定を適用します。ライブ共有は両端末を最新版に揃えて利用してください。

## 投球中の演出

投球中に残り1〜12点になると「リーチ」と必要な点数を表示します。2回連続ミスのときは「次のミスで失格」を警告し、両方の状態が重なった場合は両方表示します。スコア欄では他の選手・チームの状態も確認でき、画面下部の記録ボタンのそばにも現在の状態を表示します。チーム戦ではチーム単位の得点と連続ミスを使います。

## 試合終了後の分析

試合が終了すると分析画面が表示されます。勝敗と試合日時、選手/チームごとの投球数・得点成功率・平均/最高得点、試合中の得点推移、選手/チームごとの列に分けた投球履歴を確認できます。結果画像を共有でき、共有シートに対応しないブラウザーではPNG画像を保存してSlackなどに添付できます。

右上のハンバーガーメニューから「試合履歴」を開き、試合を選ぶと過去の結果も確認・共有できます。メニュー、履歴、個人分析は現在の画面に重なるモーダルで表示し、開いている間は背後の試合を操作できません。「戻る」で履歴やメニューへ戻り、×で閉じると元の画面へ戻ります。進行中の試合や選択中のピンは維持します。

ルール・保存や共有の仕様・各分析指標の計算方法は、メニューの「使い方・分析指標」にまとめています。通常の登録画面・投球画面・個人分析やその共有画像には、操作に必要な案内と結果を表示します。

メニューの「モルック入門」では、道具・用語、並べ方や得点・勝敗などの基本ルール、基本の下手投げ・縦投げ・裏投げ・ラハティ投げの特徴を確認できます。説明には日本モルック協会の参考リンクを添えています。

試合履歴の「全試合の個人分析」からプレイヤーを選ぶと、終了済み試合を対象にプレイヤーIDごとの成績を確認できます。参加試合数、勝利数/勝率、投球数、合計/平均得点、成功率、10点以上の投球率、最高得点に加え、成功率・平均得点・10点以上率・安定度のレーダーチャートを表示します。チーム戦の勝利は所属メンバー全員に加算し、安定度は成功投球の得点のばらつきから算出します（成功投球2回未満は未計測）。選択中のプレイヤーの成績とレーダーチャートは、共有シートまたはPNG画像の保存からシェアできます。

個人分析の「あがり成功率」は、投球前に38〜49点（残り1〜12点）の場面で、ぴったり50点にできた割合です。成功数と機会数を併記し、レーダーチャートにも表示します。ミス・点数不足・50点超過も機会に含めます。チーム戦ではチームの投球前得点を基準に、実際に投げた本人へ集計します。対象の投球がない場合は未計測です。狙ったピンは記録していないため、投球結果に基づく指標です。既存の試合履歴からも計算できます。

10点以上率は、投球前に残り13点以上（得点が0〜37点）の投球のうち、10点以上を取った割合です。ミスも分母に含め、残り12点以内での投球は分子・分母の両方から除外します。チーム戦ではチームの投球前得点を基準に、実際に投げた本人へ集計します。対象の投球がない場合は未計測です。

## ライブ共有・観戦

メニューの「ライブ共有・観戦」で共有を開始します。試合開始前から接続でき、子端末は開始待ちの状態から試合開始に自動で追従します。親端末は接続URL・接続文字列のコピー、共有シート、QRコード表示ができます。子端末はURLを開くか、同じメニューでURL・接続文字列を貼り付けて観戦します。URLの `#watch=...` に接続情報を保持するため、GitHub PagesのサブディレクトリやPWAでも同じ方式で動きます。

子端末は閲覧専用で、得点・投球履歴・試合終了をリアルタイムで表示します。取り消しや次の試合にも追従し、各端末自身の保存データは変更しません。親は現在の試合だけを送り、過去の試合履歴は送信しません。接続先ごとに接続文字列を照合し、子からの編集メッセージは受け付けません。接続は最大16台です。

PeerJS公開サーバーへの利用登録やAPIキーの取得は不要です。`liveTransport.ts` でSTUNのみを明示設定し、PeerJS標準設定に含まれるTURNは使いません。直接接続できない回線の組み合わせでは接続失敗を表示します。初回接続は約30秒、接続後の更新途絶は約20秒で判定し、最後の受信内容を残して再接続を選べます。親が共有を停止したり、アプリを閉じたりすると共有は終了します。画面ロック・バックグラウンド移動で通信が停止する場合もあります。

通信は保存JSONとは別の `molkky-fun/live` プロトコル（version 3）です。親がrevision付きの全体スナップショットを配信し、子は試合の妥当性・セッション・revisionを検証します。接続処理、通信形式、閲覧画面を分け、将来の編集要求を追加できる構成にしています。

## 過去の参加者を再利用

新しい試合の登録画面の「試合履歴から追加」を開くと、過去の試合の参加者を選んで追加できます。同じプレイヤーIDを使うので個人成績を引き継ぎ、追加済みの参加者は重複追加できません。不要な参加者は×で外し、2人以上にして試合を開始してください。チーム戦では追加後に所属チームを変更できます。

## データのバックアップ

右上のメニューの「データを書き出す」から現在のゲームと試合履歴をJSON形式で書き出し、「データを読み込む」から読み込めます。読み込み時は、現在の保存データがファイルの内容に置き換わります。エクスポートしたファイル名も Molkky Fun に統一しています。

## スマホのホーム画面に追加

HTTPSで公開したサイトを開き、以下の操作で追加できます。

- iPhone / iPad: Safariの共有メニューから「ホーム画面に追加」を選択します。
- Android: Chromeのメニューから「ホーム画面に追加」または「アプリをインストール」を選択します。

ホーム画面のアイコンからブラウザーのアドレスバーなしで起動できます。本番ビルドでは初回オンラインアクセス時にアプリを保存し、保存完了後はオフラインでも利用できます。更新はアプリの全ウィンドウを閉じて開き直すと反映されます。開発サーバーではオフライン保存を行いません。

試合データは引き続き端末のローカルストレージに保存されます。追加前のデータが見えない場合は、元のブラウザーでJSONを書き出し、追加したアプリで読み込んでください。

## 保存JSONのスキーマ（開発者向け）

`public/app-data.schema.json` にJSON Schema Draft 2020-12形式で保存データを定義しています。公開後はサイト直下の `app-data.schema.json`（GitHub Pagesでは `/molkky-fun/app-data.schema.json`）を直接開けます。アプリ内のメニューにはリンクを設けていません。

公開スキーマは、現在のアプリが保存・書き出す最新構造だけを定義し、簡易入力と詳細入力の使用例を `examples` に記載しています。試合は `mode`・`settings`・`sets` を持ち、各投球の `points` は必須です。端末の現在設定は含めません。旧形式の定義や使用例は公開せず、互換読み込みは `readMatchData` で引き続き行います。旧ファイルを検証したい場合も、読み込み時に変換した後の構造がこのスキーマの対象です。IDの参照整合性や投球順、履歴の試合が終了済みであることは、アプリ側で追加検証します。

## GitHub Pagesへの公開

`main` ブランチへの push で GitHub Actions がビルド・デプロイします。GitHub リポジトリの Settings > Pages で、公開元に GitHub Actions を設定してください。
